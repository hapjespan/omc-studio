## Format

`- [ ] T### [P] [US#] [complexity: high] description. Files: ... Accept: ... WCAG: ...`

- **[P]**: the task's files are disjoint from its neighbours and it depends on no open task. `.workflow/parallel-plan.py` only ever narrows this. `lang/nl.json` and `routes/web.php` are exempt from the disjoint-footprint rule of parallel sections and are merged in section order (tasks that add Dutch labels edit the first, tasks that wire a route the second); it appears in the files of tasks that add Dutch labels, so those tasks serialise.
- **[US#]**: the user story of `spec.md`. Setup, foundation and polish tasks carry none.
- **[complexity: high]**: only for a cross-cutting change, a data migration, tricky concurrency or a security boundary; the reason follows in plain text. Standard tasks carry no marker. Editing this flag in a commit is the only way to escalate a task (docs/process/05-tasks.md).
- **Accept**: the acceptance criteria in short form with scenario, FR and ADR references. **WCAG**: the baseline items WB1 to WB12 of the spec ("Accessibility baseline") plus the criteria the story adds; non-user-facing tasks carry none.
- **Section**: one `## Phase` per context window, at most 20 tasks, ending in a **Checkpoint** line. A section with **Parallel with** has a file footprint disjoint from the named sections.
- Labels in Dutch are quoted and live in `lang/nl.json`; code, identifiers, paths and commits are English.
